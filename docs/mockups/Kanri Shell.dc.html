kanri · app shell

Two shapes for two scopes, one bar of chrome.

A vertical list is always the app. A horizontal capsule is always the project. The only chrome above a widget is a single 44px bar.

Where each need lives

App nav → sidebar. Five fixed items, same list on every route; it never gains project children, so it never reflows. Collapses to a 48px rail (⌘B); the choice persists and is never changed automatically.

Project nav → capsule in the top bar. The project name and its four views sit inside one bordered group. The name is the scope and the tabs belong to it. Rows vs. segmented pills is the difference, not colour.

Switching → the name is the switcher. Clicking the name (or ⌘P) opens a searchable list of recent and active projects. The switcher keeps your current view, so Board opens Board. It works the same whether the sidebar is collapsed or not.

Rules the bar follows

Outside a project the capsule is replaced by the page title in the same slot. No greyed-out tabs, no "select a project" placeholder, and the bar keeps its height.

Primary action always sits at the far right of the bar, and there is only one per route. Secondary actions (Edit project, Open estimate, Archive) go in the ⋯ menu beside it.

Lime marks exact location + the one action. Inside a project the active view tab is lime; sidebar "Projects" drops to neutral accent as the ancestor. On Estimates, the sidebar item is lime.

Trade-offs

Rejected: views nested in the sidebar. It saves the 44px bar, but the sidebar would grow on project routes and shrink elsewhere, and in the collapsed rail you'd get four unlabelled icons with no project name.

Cost: 44px above the Gantt. In exchange there is no page header, breadcrumb row, or tab strip. Title, scope, views, search and action all share that one bar. At 1280×800 the widget gets 756px.

Widgets own their area. Board, Gantt and Docs render edge-to-edge with no padding, and the inset doesn't scroll. Turn off SVAR's own "add" button so it doesn't duplicate the shell's.
